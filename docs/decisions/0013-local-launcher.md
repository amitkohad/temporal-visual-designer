# ADR 0013: Explicit persistent local-demo launcher

Status: accepted for workstation testing of the API and proof interpreter.

`nexusflow-local init|token|serve|stop` is a separate local-only composition root. It does not alter the general API factory or introduce a production fake-provider default. A strict `local-demo` settings marker identifies the installation; serve binds only `127.0.0.1` and has no externally bindable host option. Temporal uses a required explicit/environment/PATH CLI executable (verified with CLI 1.9.1) and a disk-backed SQLite database. No silent download, arbitrary remote target or adoption of an occupied port occurs.

Initialization creates installation-specific RSA signing material, trusted local JWKS, real SQLite providers, one Dev business-author grant and a safe welcome project. Tokens use the existing strict verifier's Entra-shaped claims with a demo-specific audience and local trust key; they are synthetic credentials, not live Entra authorization. The ordinary identity repository provisions all three placements, while local credentials/configuration/runtime support only Dev. Local configuration revision `local-v1` represents the immutable empty configuration, validated against the project's actual schema. Custom Python activity capabilities always reject: no fake executable activity support is advertised.

The initialization settings marker is published only after keys, stores and actual welcome publication/activation complete. Reinitializing a recognized installation validates it without overwriting edited projects, keys, revoked grants or partial state. Unknown populated directories and incomplete/mismatched metadata fail closed. The initial runtime adapter cannot execute/query during initialization. Signing and provider code do not import test helpers. Token lifetime defaults to one hour, bounded by 24 hours; token reads can occur while serving.

An OS file lock covers the full init/serve lifetime across processes; the stable lock inode is never deleted. Shared package/environment changes remain coordinator-owned when sub-agents work concurrently. Serve reserves the API port first, owns its local Temporal process, verifies namespace state/retention and starts the real proof worker before HTTP begins. The runtime persists and verifies exact scope/namespace/queue/port identity. Missing one of the Temporal history/dispatch journal pair fails closed; the launcher never recreates a clean history beside known receipts. Other partial startup states require explicit recovery, not automatic deletion.

`stop` writes an installation-bound local marker; the running launcher observes it asynchronously and initiates normal Uvicorn shutdown. A stale marker is removed before a new serve starts; stop is intended for an already running launcher, not future-launch scheduling. Normal context unwinding closes API repositories, worker, dispatch journal and owned Temporal server and releases the lock even on errors. The cross-platform stop command avoids relying on Windows TerminateProcess for cleanup. Forced process termination cannot guarantee clean shutdown and remains outside the normal acceptance path.

The state directory is one preservation unit, containing credentials, provider stores, activation/start intents, dispatch receipts and Temporal history. Runtime destination changes or partial database deletion require investigation/new demo state. Journal permanence does not imply indefinite Temporal query-history retention. The configured namespace is verified with at least one day of retention; production backup/recovery, RPO/RTO, HA and long-term retention remain open. Unix private-key creation uses exclusive mode 0600; Windows relies on inherited workstation ACLs. Workstation state is trusted, private and never an uploaded deployment package.

Operational output identifies profile/address/scope, not bearer tokens, inputs or keys. Token is emitted only by the explicit token command. Access logging is disabled; the local host is not an external telemetry redaction or production TLS solution. Local exception output is sanitized. Live Entra, custom activity sandboxing, connector effects, browser UI, task inboxes and production deployment remain separate increments.

Three disjoint agent lanes implemented bootstrap/provider composition, runtime lifecycle and independent socket/subprocess acceptance. The coordinator implemented CLI locking/stop, integrated all lanes, corrected cross-platform type checking and aligned port validation. Isolated tests cover initialization, retention-state failures, lifecycle cleanup, namespace failures and locking. Actual CLI/socket/worker acceptance verifies persistence and authenticated workflow completion across graceful restart without ASGI-only transport.
