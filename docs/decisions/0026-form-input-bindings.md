# ADR 0026: Workflow-input bindings for managed form initial values

Status: accepted for a bounded host-side input binding subset.

Reuse the existing versioned binding envelope only as a complete top-level managed-form initial field value: `{"$binding":{"schema_version":"0.1","source":"input","path":"/employee/name"}}`. A selected source must follow declared required object properties in the workflow input schema and have a provably compatible type. Use strict JSON Pointer decoding; reject malformed escapes, array traversal, step outputs, expressions, defaults and external lookup. Whole values may be copied when their target schema accepts them. Existing interpreter schema restrictions remain in force.

Validate declarations during activation against the original workflow schema without synthesizing business inputs. A public structural-validation function returns no executable plan; the executable compiler has no public option to skip input validation. Actual starts validate the supplied workflow input, resolve selectors, validate the selected values against target field constraints and formats, and apply existing form size/depth limits before reserving a start intent. Never mutate caller-owned definitions, schemas or inputs. Failures are sanitized and contain no selected values.

Preserve the original definition digest and declared step input JSON. Only the compiled approval configuration contains materialized literal initial values; it is persisted with the immutable start plan. The existing input fingerprint rejects changed data under the same idempotency key, and retries retain the original release/plan even after edits or activation changes. No workflow activity command or transport shape changes are needed. No-binding and literal-form canonical bytes remain unchanged.

The worker accepts only literal form snapshots and rejects unresolved or nested binding syntax before any task or destination write. Reserved syntax remains unsupported everywhere outside the explicitly recognized field position. Reject selected data containing reserved binding markers so data cannot become deferred executable syntax. Structural validation does not make initial values a validated participant submission: an explicit successful form submission is still required before approval.

Existing field policy and read/write annotations control form visibility; arbitrary workflow input carries no new secrecy classification. Mapped readable fields are intentionally visible in form previews. Ordinary task/status/audit responses remain payload-free. Output bindings, runtime activity mappings, optional/default/array-path semantics, general expressions, reference-schema support, reusable project-form resolution and React mapping controls remain separate work.
