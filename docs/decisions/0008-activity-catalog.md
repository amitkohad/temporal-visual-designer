# ADR 0008: Scoped immutable catalog and lifecycle

Status: accepted for local backend F04-T001b/T003/T005.

Publish from a validated intake candidate only after fresh activity.publish authorization, full archive/manifest integrity revalidation and an explicit destination RuntimeCapabilities provider check. Operators can inject the same IntakeLimits into IntakeService and CatalogService; fresh publication revalidation enforces the configured destination policy rather than fixed defaults. The capability provider is mandatory; no default accepts every runtime. It must evaluate the declared Python version, dependencies and runtime requirements without running user code. Existing publication retries return the original catalog record even when the capability provider later fails or the version becomes deprecated/withdrawn. Retries never reset lifecycle state.

Store immutable manifest/archive snapshots in the catalog, independently of intake. Uniqueness is organization/environment/activity/version; digest mismatch cannot replace a version. Scope every lookup, search, audit, export and usage hold. Local SQLite transactions commit lifecycle/audit records together. Logical catalog purge clears its archive but leaves the version reservation and audit trail; publishing that version again conflicts. Private intake copies have their own future cleanup policy; catalog purge is not secure erasure of every source copy.

The lifecycle is published -> deprecated -> withdrawn, with published -> withdrawn also allowed. Generation checks reject stale changes; setting the already-current target is idempotent and creates no duplicate event. No operation restores a withdrawn version. Deprecation hides a version from default palette search while preserving exact pinned resolution and export. Withdrawal hides it from every palette search and blocks new resolution/usage holds. Existing server-managed holds can still fetch the artifact for retained use; that export does not authorize a new deployment or execution.

Usage holds are an internal repository port. Acquire before release/run use; release only after retention ends. New holds and deletion serialize with withdrawal, so a retained artifact cannot be purged. Only withdrawn, unreferenced catalog entries may be purged. Automatic project-publication/run hold acquisition, compensation/outboxes, distributed retention and deployment withdrawal enforcement remain F04-T006/runtime/promotion integration. The current ScopedCatalog resolver is read-only and does not create holds. Do not expose a production garbage collector before those consumers participate in retention.

CatalogService requires activity.read for metadata/search/resolution/audit, activity.publish for publication/lifecycle/purge, and package.export for artifact exports. Business authors now receive activity.read in Dev/UAT; they receive no activity.import or activity.publish rights. Production business-author restrictions remain. IdentityCatalogAuthorization verifies the token and server grants on every request. Hold IDs must come from trusted release/execution controllers, not be treated as caller-supplied proof of ownership. Resource-specific project ACLs and public HTTP routes remain separate work.

Search uses casefolded literal substring matching across ID/display name/description, exact category filters, SQL state filtering and bounded pagination. Results sort deterministically by activity ID and lexical version; there is no mutable latest-version alias. Metadata queries never fetch artifact BLOBs. SQLite JSON metadata filtering and a scoped state index are the local provider, not a measured production full-text/search-capacity guarantee.

The app composition adapter supplies fresh descriptor copies and pinned bundle resolution to AuthoringValidator/ProjectService. Python dependencies are already vendored inside each sealed source bundle, so no separate mutable dependency registry is consulted. Whole-bundle export can be validated/imported in UAT with no original registry. This is artifact closure portability, not Feature 09 project-package promotion.

This increment is a Python library/backend adapter. Admin/Designer UI, secured HTTP transport, actual worker capability discovery/probes, isolated Python execution and production migrations remain open. Workers will need a separate execution-bound artifact adapter; do not grant broad package.export rights to worker identities. Local audit events are not tamper-evident storage.
