# ADR 0012: Explicit authenticated application API

Status: accepted for the initial Python HTTP/application composition boundary.

Use FastAPI with Uvicorn as the ASGI host. Python 3.12/3.13 remain supported; dependencies are locked in `uv.lock` (FastAPI 0.162.0, Starlette 1.9.0, Uvicorn 0.54.0). HTTPX provides async ASGI integration tests and HTTPX2 supplies the current Starlette synchronous TestClient transport. This introduces no browser framework change: the browser remains React.

`create_app(ApiBackend(...))` requires explicit identity, project/catalog/intake/activation/start providers, destination configuration/capability ports and a runtime gateway. It never creates permissive identity, fake workers or a production deployment from test helpers. Provider initialization, database/bootstrap configuration, Temporal clients/workers, shutdown and deployment are owned by a future host/launcher; the factory does not own injected resource lifetimes. A configured host module can serve the application with Uvicorn now. There is no zero-configuration launcher or React application in this increment.

All business routes are under `/api/v1/organizations/{organization_id}/environments/{environment_id}` with explicit Dev/UAT/Prod paths. Bearer tokens are required; signed-token verification, organization membership, fresh server grants and environment existence are enforced by the existing identity service. Domain operations reauthorize their own permissions. Scope is not trusted from bodies, nor are client roles, Temporal namespaces or task queues. Registry placement selects the namespace/queue; the actual Temporal gateway verifies client namespace before dispatch/query. Identity uses injected trusted signing-key/group providers; live JWKS/Graph adapters remain open. Existing coarse environment-scoped grants are not fine project ACLs.

The API exposes project list/create/current-or-revision read/save/validation/publication, catalog search, project activation/current activation and workflow start/status. Pagination bounds project/catalog lists. Existing services remain authoritative for project/form/graph/digest/publish/activation/start semantics. Transport responses have typed models in OpenAPI; raw project content is an object, while the internal repositories continue to use canonical JSON. Activation/start/status views exclude stored complete release snapshots, workflow input and activity output payloads.

Run status first authorizes `run.read` and proves organization/environment/project ownership through the persisted start intent before invoking Temporal. A pending intent returns `dispatch_pending` without remote inspection. A returned runtime snapshot must match the pinned release, definition digest and interpreter. Status exposes the existing proof snapshot, not a full execution projection/debugger. Repeating start requests preserves the domain idempotency key and pinned plan; external delivery remains governed by the permanent dispatch journal.

An ASGI boundary assigns server-generated correlation IDs, applies `no-store` responses, bounds actual body bytes (default 6 MB), rejects malformed/oversized content-length and encoded bodies, and checks body size even without content-length. Headers do not grant authority. Field/JSON/domain/provider errors are converted into sanitized versioned envelopes with stable 401/403/404/409/422/503 statuses; unexpected failures return a generic 500. Request validation never echoes input or tokens. Error messages follow the existing shared envelope; authoritative validation issues are returned by the separate validation endpoint. The health route is unauthenticated process liveness only, not provider readiness.

Interactive documentation is disabled; scoped authenticated `/schema` serves OpenAPI including bearer security definitions. Public docs do not expose resource data. No cookie auth or CORS wildcard is added. Gateway TLS, rate/connection/deadline limits, external telemetry redaction, retention and deployment readiness remain host/platform responsibilities. Buffering and local SQLite are bounded local implementation choices, not measured production concurrency guarantees. In-flight operations authorized before revocation may finish; later requests recheck grants.

Default HTTP tests use actual ASGI transport, signed synthetic RSA tokens and real SQLite stores with explicit configuration/capability/runtime fixtures. A separate real Temporal test registers the trusted environment namespace, uses the actual gateway/dispatch journal, starts through HTTP, waits for completion, reads the safe status and retries the same start. These do not establish live Azure/Entra or browser acceptance. No module imports test helpers in application code.

Framework references consulted 2026-10-24: [FastAPI error handling](https://fastapi.tiangolo.com/tutorial/handling-errors/) and [FastAPI testing](https://fastapi.tiangolo.com/tutorial/testing/). Exception handlers are deliberately customized to avoid returning request validation payloads.
