# ADR 0007: Bounded Python source-bundle intake

Status: accepted for the local intake increment (F04-T001a/T002).

Accept a ZIP containing root manifest.json and explicitly declared Python source files under src/. ActivityManifest 0.1 includes the common descriptor, a Python-specific runtime declaration, entrypoint, exact file sizes/SHA-256 values and locked vendored dependency identities. Initially accept Python 3.12/3.13 and pure-source dependencies; wheels, native extensions, installation hooks, arbitrary assets and build scripts are outside this format. Version aliases are rejected. This is an immutable preassembled source artifact; intake never installs dependencies or imports/executes user modules.

The activity digest covers the canonical complete manifest with descriptor.activity_ref.artifact_digest omitted to avoid circularity. File records are sorted by path; dependency records and their file lists are sorted. All payload files must match the manifest exactly. SHA-256 file records bind source bytes into the manifest digest, including descriptor/runtime metadata. ZIP timestamps, compression and entry order do not affect logical identity. Download preserves the first accepted original archive. Integrity checking is not publisher provenance/signature validation.

Validation is in-memory staging followed by one durable transaction: no archive extraction or filesystem staging occurs, so failed validation leaves no staged files or orphan blobs. The local SQLite provider commits metadata and archive bytes together and deduplicates organization/environment/activity/version. Identical logical retries return the existing import; a changed digest for that version conflicts. Separate connections race safely through database transactions. Production object storage/shared database providers and their migrations remain separate work.

Default configurable bounds are 8 MiB archive, 16 MiB expanded, 1 MiB source file, 256 KiB manifest, 256 ZIP entries and 100:1 expansion ratio. The manifest independently caps 200 files/100 dependencies. Reject traversal, drive/backslash/absolute/NUL/non-ASCII paths, Windows reserved names, duplicate/case-folded paths, file/directory collisions, links/special files, executable source permissions, encryption and unsupported compression. Empty directory entries are permitted. Supported archive paths are portable but are never extracted by intake.

Offline schema checks reject schema references. AST parsing checks the declared Python grammar and a conservative set of literal credential assignments/dictionaries without evaluation. Parsing newer syntax on an older host can conservatively fail. It does not certify callable signatures, import availability, resource limits or successful execution. Literal credential heuristics are not DLP: encoded/computed secrets, comments, schema defaults and arbitrary strings require additional publisher/security policy before production use.

IntakeService freshly checks activity.import for import and private candidate reads/downloads. IdentityCatalogAuthorization uses the existing signed-token/server-grant service; package import permissions confer no code-import rights. Public palette discovery and activity.read are not available here. Imported records have metadata-validation state validated only. Publication, deprecation/withdrawal, retention, export closure, capability checks and isolated execution remain F04-T003/T006/T007.

Worker dispatch, credential/network/resource sandbox policy and production artifact format extensions remain F04-T001b. No worker starts and no runtime availability is inferred from metadata validation. Do not connect private intake directly to the Designer palette or deploy imported code before the separate publication/execution gates.
